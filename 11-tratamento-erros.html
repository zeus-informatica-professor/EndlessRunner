Etapa 11 — Tratamento de erros: try...catch, finally e throw

Programas podem receber dados inválidos ou encontrar situações inesperadas. Podemos lançar um erro com uma mensagem clara e tratar a situação de forma controlada.

1. Para que serve cada palavra-chave?

  • try: contém o código que pode gerar um erro.
  • catch (erro): executa se ocorrer um erro no try e permite consultar o objeto de erro.
  • finally: executa depois de try/catch, tenha ocorrido erro ou não.
  • throw: lança um erro intencionalmente quando uma regra é violada.

Importante: o tratamento não corrige automaticamente o problema; permite responder a ele de modo controlado.

2. Exemplo: validar uma pontuação

function definirPontuacao(valor) {
  if (typeof valor !== "number" || !Number.isFinite(valor)) {
    throw new TypeError("A pontuação precisa ser um número válido.");
  }
  if (valor < 0) {
    throw new RangeError("A pontuação não pode ser negativa.");
  }
  return valor;
}

try {
  const pontos = definirPontuacao(10);
  console.log("Pontuação registrada:", pontos);
} catch (erro) {
  console.error("Não foi possível registrar:", erro.message);
} finally {
  console.log("Validação finalizada.");
}

Troque 10 por -5, "dez" e depois por 25. Observe os resultados.

3. Experimente no navegador

Digite 10, -5, texto ou deixe o campo vazio. Observe como throw rejeita valores inválidos, catch apresenta a mensagem e finally indica o fim da operação.

Aguardando validação.

try {
  // validar entrada e lançar erro se for inválida
} catch (erro) {
  // apresentar a mensagem do erro
} finally {
  // executar a finalização
}

4. Boas práticas

  • Não use catch vazio: isso esconde problemas.
  • Use mensagens claras e consulte erro.message.
  • Use throw para representar uma regra inválida, não para substituir toda condicional.
  • finally executa também quando o try termina normalmente.
  • Operações assíncronas podem exigir tratamento com async/await, assunto posterior.

5. Desafios

  1. Rejeite pontuações acima de 1.000 com um RangeError.
  2. Melhore a mensagem de erro.
  3. Conte quantas tentativas foram feitas.
  4. Explique por que finally executa mesmo quando ocorre erro.

Preparação para o jogo completo

O tratamento de erros é útil quando uma função depende de entrada válida ou quando uma operação pode falhar. Não é necessário envolver cada linha do jogo em try...catch.
