O que esta etapa demonstra?

  • createClient(): cria o cliente de comunicação com Supabase.
  • select(): consulta os jogadores cadastrados no PostgreSQL.
  • insert(): insere um novo jogador.
  • update(): altera os dados de um jogador pelo ID.
  • delete(): exclui um jogador pelo ID.
  • fetch e HTTP são utilizados internamente pela biblioteca para conversar com a API.

Esta primeira integração mantém o jogo da etapa 12 e o CRUD local da etapa 13 funcionando como antes. A tela 14 é uma experiência separada para estudar o banco remoto; nesta versão, a pontuação do jogo ainda não é enviada automaticamente ao Supabase.
