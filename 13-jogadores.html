Etapa 13 — CRUD de jogadores

Vamos preparar os dados que, nas próximas aulas, serão armazenados em um banco PostgreSQL no Supabase. Nesta etapa, a persistência continua no navegador usando localStorage.

O que vamos armazenar?

Cada jogador é representado por um objeto com identificador, nome, pontuação máxima e cor do personagem. O identificador é separado do nome para que possamos localizar e atualizar o registro sem depender de um campo que pode mudar.

CRUD: Create (cadastrar), Read (listar), Update (editar) e Delete (excluir).

Preparação para PostgreSQL / Supabase

O objeto JavaScript usa os campos id, nome, pontuacao, cor, criadoEm e atualizadoEm. Essa estrutura facilita a próxima etapa: mapear os campos para colunas SQL e substituir as operações locais por requisições a uma API.

Importante: o localStorage pertence a um navegador/dispositivo. Ainda não há sincronização entre computadores e não é um banco de dados compartilhado.
